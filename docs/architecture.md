# Как это устроено

Техническое описание «Бодрячка»: чем он удерживает Mac от сна, как устроен режим закрытой крышки и что страхует систему от сбоев.

Всё приложение — один файл [`main.swift`](../main.swift) на AppKit. Окон у него нет: в `Info.plist` стоит `LSUIElement`, поэтому приложение живёт только в меню-баре и не появляется в Dock.

## Запрет сна от бездействия

Приложение просит систему не засыпать через утверждения управления питанием IOKit (power assertions). Это штатный механизм macOS, тем же пользуется команда `caffeinate`. Права администратора для него не нужны.

| Утверждение | Что запрещает | Когда держится |
|---|---|---|
| `PreventUserIdleSystemSleep` | сон Mac от бездействия | всю сессию |
| `PreventUserIdleDisplaySleep` | выключение дисплея, заставку и автоблокировку | всю сессию, если не включён «Разрешить сон экрана» |
| `UserIsActive` | сообщает системе, что пользователь активен | обновляется каждые 30 секунд при тех же условиях |

Утверждения принадлежат процессу. Если приложение завершится любым способом, система снимет их сама, поэтому «залипнуть» они не могут.

После пробуждения Mac приложение создаёт утверждения заново.

## Режим закрытой крышки

Утверждения не действуют на закрытую крышку: macOS усыпляет ноутбук принудительно. Обойти это можно только системной настройкой:

```bash
sudo pmset -a disablesleep 1
```

Она отключает сон целиком, в том числе при закрытой крышке. В выводе `pmset -g` это строка `SleepDisabled 1`.

У этой настройки два неудобных свойства, из-за которых вокруг неё построена вся защита:

- для неё нужны права администратора;
- она не привязана к процессу. Если приложение упадёт, настройка останется включённой, и Mac перестанет засыпать вообще.

Режим крышки включается, только когда выполнены все условия сразу:

1. идёт сессия;
2. включён пункт «Не спать с закрытой крышкой»;
3. установлено правило sudo;
4. режим не выключен из-за перегрева в этой сессии;
5. Mac работает от сети, если включена настройка «Крышка — только от сети».

Условия пересчитываются каждые 5 секунд и при каждом изменении настроек. Как только хотя бы одно перестаёт выполняться, приложение возвращает `disablesleep 0`.

## Права администратора

Приложение не запускает привилегированный помощник и не работает от имени root. Вместо этого оно один раз устанавливает правило sudo, которое разрешает текущему пользователю ровно две команды без пароля:

```
<пользователь> ALL=(root) NOPASSWD: /usr/bin/pmset -a disablesleep 0, /usr/bin/pmset -a disablesleep 1
```

Правило лежит в `/etc/sudoers.d/bodryachok` с правами `0440` и владельцем `root:wheel`.

Как оно устанавливается:

1. Приложение показывает окно с объяснением. Без согласия дальше ничего не происходит.
2. Через системный запрос пароля администратора (`do shell script … with administrator privileges`) выполняется короткий скрипт.
3. Скрипт пишет правило во временный файл, проверяет его синтаксис командой `visudo -cf` и только после успешной проверки кладёт на место командой `install`.
4. Приложение проверяет, что команда действительно выполняется без пароля.

Имя пользователя перед подстановкой в правило проверяется по шаблону: латинские буквы, цифры, точка, дефис и подчёркивание. С другим именем установка не выполняется.

Что это значит для безопасности: после установки правила любая программа, запущенная от имени этого пользователя, может включить или выключить системный сон без пароля. Больше правило ничего не разрешает. Отозвать его можно пунктом «Настройки → Удалить доступ для режима крышки…».

## Страховка от «залипшего» запрета сна

Каждый раз, когда приложение меняет `disablesleep`, оно записывает в настройки флаг `lidSleepDisabledByUs`. По этому флагу любой из механизмов ниже понимает, что сон отключил именно «Бодрячок» и его нужно вернуть.

| Ситуация | Что возвращает сон | Как быстро |
|---|---|---|
| Сессия закончилась или пользователь вышел из приложения | само приложение | сразу |
| Приложению пришёл сигнал завершения (`SIGTERM`: команда `kill`, выход из системы) | обработчик сигнала запускает обычный выход | сразу |
| Приложение упало или убито через `kill -9` | сторож: отдельный процесс оболочки, который раз в 3 секунды проверяет, жив ли процесс приложения | за несколько секунд |
| Сторож тоже не сработал | фоновый агент `launchd`, который запускается раз в минуту | до минуты |
| Mac перезагрузился или выключился с отключённым сном | тот же агент: он запускается при входе в систему | при входе |
| Агент не установлен или не сработал | приложение при следующем запуске | при запуске |

Фоновый агент — это файл `~/Library/LaunchAgents/local.bodryachok.failsafe.plist` и скрипт `~/Library/Application Support/Bodryachok/failsafe.sh`. Скрипт делает три вещи:

1. читает флаг `lidSleepDisabledByUs`; если он не выставлен, выходит;
2. проверяет, запущено ли приложение; если запущено, выходит;
3. выполняет `sudo -n pmset -a disablesleep 0` и сбрасывает флаг.

Агент работает от имени пользователя и может только то, что разрешает правило sudo. Он устанавливается вместе с правилом, а при каждом запуске приложение проверяет, что он на месте, и при необходимости восстанавливает.

Вторая копия приложения могла бы сбросить состояние первой, поэтому при запуске приложение проверяет, нет ли уже работающего экземпляра с тем же идентификатором, и если есть, сразу завершается.

## Проверки во время сессии

| Проверка | Как часто | Источник данных | Что происходит |
|---|---|---|---|
| Заряд | каждые 5 секунд | `IOPSCopyPowerSourcesInfo` | при работе от батареи ниже порога сессия завершается |
| Перегрев | каждые 5 секунд и по уведомлению системы | `ProcessInfo.thermalState` | при состоянии `serious` или `critical` режим крышки выключается до конца сессии |
| Крышка | каждую секунду, пока действует режим крышки | свойство `AppleClamshellState` узла `IOPMrootDomain` | в момент закрытия экран блокируется |

Блокировка экрана вызывает функцию `SACLockScreenImmediate` из системной библиотеки `login.framework`. Это та же функция, которой пользуется пункт «Заблокировать экран» в меню Apple, но она непубличная. Если её не окажется, приложение выполнит `pmset displaysleepnow`.

Температуру приложение само не измеряет. Оно полагается на оценку, которую даёт macOS.

## Сессии и таймер

Сессия описана перечислением `Session`:

| Вариант | Смысл |
|---|---|
| `indefinite` | бессрочно |
| `until(Date)` | до момента времени. Таймеры на минуты и часы тоже превращаются в этот вариант |
| `whileApp(pid, name)` | пока жив процесс выбранного приложения |

Раз в секунду срабатывает таймер. Он проверяет, не закончилась ли сессия, запускает проверки из предыдущего раздела и обновляет значок. Таймер добавлен в общие режимы цикла событий, поэтому отсчёт идёт и при открытом меню, и при открытом окне приложения.

Оставшееся время считается от момента окончания, а не вычитанием секунд, поэтому сон Mac его не сбивает.

Когда сессия заканчивается сама, причина сохраняется и показывается в меню до следующего запуска сессии. Ручная остановка причину не записывает.

## Значок в меню-баре

- Значок — системный символ `cup.and.saucer`, закрашенный вариант во время сессии.
- Левый клик открывает меню, правый клик или ⌃-клик переключает бессрочную сессию.
- На Mac с вырезом камеры новые значки могут оказаться под вырезом. Приложение при первом запуске задаёт значку желаемое место ближе к правому краю. Значок можно перетащить, зажав ⌘.
- Если запустить приложение повторно, меню откроется под курсором. Это запасной вход на случай, когда значка не видно.

## Ключи настроек

Настройки хранятся в домене `local.bodryachok`.

| Ключ | Тип | По умолчанию | Назначение |
|---|---|---|---|
| `allowDisplaySleep` | логический | нет | разрешить сон экрана |
| `closedLidMode` | логический | нет | режим закрытой крышки |
| `lidOnlyOnAC` | логический | нет | режим крышки только от сети |
| `lockOnLidClose` | логический | да | блокировать экран при закрытии крышки |
| `batteryLimit` | целое | 20 | порог заряда в процентах, 0 отключает |
| `startOnLaunch` | логический | нет | начинать сессию при запуске |
| `lidSleepDisabledByUs` | логический | нет | служебный флаг: сон сейчас отключён приложением |
| `askedNotifications` | логический | нет | служебный: разрешение на уведомления уже запрашивалось |
| `welcomed` | логический | нет | служебный: приветственное окно уже показано |

Посмотреть текущие значения:

```bash
defaults read local.bodryachok
```

## Сборка

[`build.sh`](../build.sh) делает всё без Xcode-проекта:

1. компилирует `main.swift` дважды, для `arm64` и `x86_64`, с минимальной версией macOS 13;
2. склеивает два файла в универсальный командой `lipo`;
3. компилирует и запускает `make_icon.swift`, который рисует иконку 1024×1024;
4. нарезает иконку на размеры командой `sips` и собирает `AppIcon.icns` командой `iconutil`;
5. пишет `Info.plist`;
6. подписывает приложение локальной подписью (`codesign --sign -`).

С флагом `--install` скрипт закрывает работающую копию, кладёт новую в `/Applications` и запускает её. С флагом `--dist` собирает образ `Бодрячок.dmg`, в котором лежат приложение, инструкция и ярлык папки «Программы».

Локальная подпись не заменяет подпись разработчика Apple. На Mac, куда приложение попало через интернет, первый запуск блокируется.

## Как проверить вручную

Держит ли приложение запрет сна:

```bash
pmset -g assertions | grep Bodryachok
```

Во время сессии в ответе должны быть строки `PreventUserIdleSystemSleep` и, если сон экрана не разрешён, `PreventUserIdleDisplaySleep`.

Действует ли режим закрытой крышки:

```bash
pmset -g | grep SleepDisabled
```

`1` означает, что сон отключён и крышку можно закрывать. Вне сессии должно быть `0`.

Установлено ли правило sudo:

```bash
sudo -n -l | grep pmset
```

Работает ли фоновый агент:

```bash
launchctl print gui/$(id -u)/local.bodryachok.failsafe | grep -E "runs|last exit"
```
